# 手机长文阅读参数

## 参数优先级与边界

用户本次明确指定或试读确认的参数 > 所选主题默认值。主题中的“固定字号”不是微信平台限制；用户有调整要求时按文字用途覆盖，不做全局等比例放大。

小步生长、向前一格、摸鱼蓝默认正文 **16px、行高1.8**。该值来自本地主题选择和手机试读反馈，是可调整的设计起点，不是微信公众号官方标准，也不是WCAG的最低字号要求。16px的直接手机偏好反馈来自摸鱼蓝；另外两套采用相同基线，仍要检查自身卡片行宽和换行。

## 按用途应用

| 文字用途 | 这三套主题的默认处理 |
|---|---|
| 连续正文、实质导语、列表项、步骤说明、问答正文 | 16px，行高1.8 |
| 人物引语、金句中的完整句子、提示／旁注中的实质内容 | 16px，行高1.8，不因放进卡片而降为小字 |
| 行内加粗、下划线、荧光笔 | 继承所在正文的字号，不额外缩小或加大 |
| 封面、章节标题、小标题、章节序号 | 保留主题层级，按自身字数与换行判断，不跟随正文同比放大 |
| 目录短标题、栏目标签、来源、图注、作者简介、文末互动 | 保留各主题的辅助层级；重要的完整说明不能借此塞成小字 |
| 代码、命令、数据表格 | 按自身密度单独检查，不能为了塞下内容一律缩小；不套正文倍率 |

段间距与行宽保留各主题特征：摸鱼蓝正文段后20px、字距0.5px、左右20px；向前一格与小步生长正文段后22px、字距0.25px，正文、刊头、封面外侧及文末额外左右内收8px。向前一格原正文24px／封面20px叠加微信页面边距后被用户反馈过宽，随后用户要求小步生长也从24px收窄；8px是主题内部追加量，不是微信官方规范。不要重复套边距容器，导致正文每行字数过少。

### 向前一格与小步生长的行宽设置

| 位置 | 当前默认值 |
|---|---|
| 正文及章节容器 | 左右margin各8px，只套一层 |
| 刊头、文末 | 额外左右各8px，与正文对齐 |
| 封面卡片外侧 | 左右margin各8px |
| 封面内部留白 | 向前一格卡片左右padding各23px；小步生长导语卡各17px |
| 整篇文章最大宽度 | 677px；窄屏随可用空间收缩 |

这些值仅作用于向前一格和小步生长。正文仍为16px／1.8、段后22px；调整行宽不应把封面内部padding也改成8px。微信页面自身留白由客户端决定，不能把主题8px表述为手机屏幕到正文的总间距。

继续使用主题自带系统字体栈，不依赖下载字体。正文用正常字重，重点靠少量局部强调；字号增大不代表正文需要整体加粗。

## 落实到HTML

- 对真正承载正文的元素写明确的内联字号、行高；检查子元素是否又指定了更小字号。
- 调整时同步普通段落、正文列表、引用、提示、完整模板骨架及对应预览。不能只改变量说明。
- 同一元素的 `font-size` 和 `line-height` 只保留最终值，避免“前面16px、后面旧14px”导致实际未生效。
- 不把正文值设为所有后代的强制覆盖。标签和编号可以保留独立层级；行内强调通常不另设字号。
- 沿用通用增量库时按语义适配：例如3e提示的实质内容跟随正文，类型小标签不变；代码块和图注独立处理。
- 阅读参数调整不重写文章内容、不改变用户确认的装饰骨架，不回写已经发布的历史稿。

## 检查

1. 运行组件源头检查和产物HTML校验，确认平台兼容与文本包裹。
2. 用实际长段落检查至少320px和390px宽度下的正文、列表、引用，确认字号、行高、强调继承、换行与无横向裁切。
3. 另外检查文字／背景对比度。不能用更大字号掩盖过浅文字，颜色修订须单独明确范围。
4. 发布前在正式微信预览里检查；手机网页确认不能替代微信公众号客户端，未验证时如实说明。

WCAG的可覆盖间距测试不是默认排版配方。Web端不要禁止用户缩放，也不要将设备物理像素、CSS px和原生App字号混为一谈。
