# 触发与主题选择 · 回归用例

维护本 skill（改 description、加主题、调路由）后用这组用例核对，确保该触发时触发、不该触发时不触发、主题推荐合理。

## 正例（应触发 gzh-design）

- "帮我把这篇 Markdown 做成公众号排版"
- "微信公众号文章排版"
- "gzh，这篇用 XX 主题"（XX 为 theme-index 中已注册主题）
- "把下面这篇文章转成能直接粘进公众号编辑器的 HTML"
- "这篇文章帮我排个版，发公众号用"
- "给公众号排版生成一套新主题 / 自定义风格"（→ 自定义主题生成流程）
- "按这张参考图帮我做一套公众号排版组件库"（→ 自定义主题生成流程）

## 反例（不应触发，应转其它能力）

- "帮我做一个网页落地页" → 前端/web skill
- "把内容做成 PPT" → PPT skill
- "帮我排版这个 Word 文档" → 排版对象不是公众号
- "写一篇公众号文章" → 这是写作，不是排版（先有 Markdown 才用本 skill）

## 主题选择行为（自动推荐制）

- 用户指定了 theme-index 中已注册的主题 → 直接执行不提问
- 题材有明确契合 → 单问确认「建议用 XX（理由），确认还是换一套？」，选项给推荐项 + 1~2 备选 + "看全部"，不擅自定死
- 题材无明显倾向 → 默认把 theme-index 第一行（摸鱼绿）作推荐项放第一位，让用户在几套里选
- 用户明说"直接排/一键/不用问" → 全自动例外：自动选题材最契合主题，交付时说明理由
- 用户选定主题后 → 在该主题内部按"文章类型 → 组件组合配方"匹配组件
- theme-index 为空（无已注册主题）→ 不排版，告知用户先添加主题风格，不要凭记忆编造主题

## 关键行为核对（用 assets/sample-article.md 或含代码块/图片的文跑一遍）

- [ ] 选主题默认把 theme-index 第一行主题放第一位
- [ ] 解析结构后判定了文章类型，并按主题库「文章类型 → 组件组合配方」表选组件组合（不是逐段随机选）
- [ ] 点缀组件种类不超过配方表规定的上限
- [ ] 目录/导航组件位置符合主题骨架（摸鱼绿：toc-scroll 紧跟封面之下，在引言和前言之前）
- [ ] 晴空手记（原摸鱼蓝）及同系多色主题（鸢尾快讯、铅字刊物、落日工坊、绯莓微刊）封面为从正文提炼的独立导语，和文章标题互补；保留栏目／月份、关键词、来源及主题标签的杂志层次，缺少单个事实字段时不整行删除。日期来自作者刊期或实际排版时钟，不编造活动时间。
- [ ] 正文引号生成时即为全角弯引号，无需事后替换
- [ ] 代码块走代码块组件，不塞进段落
- [ ] 图片用图片组件、GIF 加动图角标
- [ ] 正文半角标点被改成中文全角（代码块内不动）
- [ ] 开头引言卡署名按文章作者/主题定，不固定"甲木"
- [ ] 尾部签名区默认用 `{{作者名}}` 占位（不写死人名）；用户给了署名才填入，原文已有签名则沿用原文
- [ ] 原文已有签名段时合并进唯一签名区，不重复
- [ ] 强调/小标题用小标签或左竖条，无虚线框
- [ ] 代码块紧凑：每行一个 `<p style="margin:0">`，无 `white-space:pre`，无大段空白
- [ ] `【插入…】` 类待补占位用 2c 居中板块，不是左对齐提示块
- [ ] 骨架按所选主题库的"完整文章模板骨架"装配，不套用其它主题骨架
- [ ] 生成后跑 scripts/validate_gzh_html.py，ERROR 与半角 WARNING 清零

## 自定义主题生成行为

- 用户说“用小步生长／向前一格／晴空手记（或鸢尾快讯、铅字刊物、落日工坊、绯莓微刊）” → 直接读取对应已注册组件库，不再重新生成风格；默认正文与内容引用16px、行高1.8
- 用户说“正文改17px，标题别动” → 只覆盖正文类组件及内容引用，行内强调继承；不把标题、封面、编号、标签批量改成17px
- 使用摸鱼绿但指定16px → 用户参数优先于原版14px默认值；不以旧版固定字号为由拒绝或遗漏覆盖
- 使用 16px 扩展主题中的提示、列表、引语 → 检查实际内联样式，不只是文档中的设计变量；代码和辅助字不一并放大
- 从主题预览取组件 → 不将组件示意标签、预览id、工具栏或作者示例身份带入成文

- 用户说"生成新主题"但只给一句风格描述 → 一次性问全偏好字段（不逐字段追问），空缺项按 theme-generator.md 规则自动补全
- 用户上传参考图 → 先 Read 提取视觉特征，只做风格转译，不复刻图中文字/Logo/构图
- 生成的区块库 HTML 保存到 `assets/theme-previews/{theme-id}.html`，全部区块在一页内连续排布，用户**整页一次浏览**确认风格（不逐块展示、不逐块确认），再转标准主题库
- 转换 `theme-{标识}.md` 时：补 `<span leaf="">`、去掉预览用 `id`、补齐五章节（变量表/组件/骨架/配方表/映射表）
- 新主题登记进 theme-index.md 且 `component_lint.py` 0 ERROR 后才算交付；之后"列全部主题让用户选"必须包含它
- 主题 ID 与已有主题冲突 → 提示换名或确认覆盖，不静默覆盖

## 格式兼容用例

- 给 `.docx` → 先跑 `scripts/extract_docx.py` 转 md，再结构确认，不直接读二进制
- 给 `.pdf` → Read 分页读取，删页眉页脚页码、合并硬断行，图位留居中占位
- 给无标记 `.txt`（含"一、二、"式标题）→ 正确推断为 `##`，结构确认后再排
- 给完全无标题的纯文本 + "直接排" → 全自动：语义分章 + 自拟标题 + 自选主题，交付附决策说明
- 给 `.doc` 老格式 → 提示另存为 .docx，不硬解析

## 维护 · 可验证循环

### 装饰图标的保存回归

2026-11-11用真实macOS剪贴板读取定位：浏览器默认选区复制在进入微信之前已经丢掉首个空背景方片。此前将顶部改成与文末相同的18px图标和p容器仍失败，排除了“仅换容器即可修复”的假设。不能再把微信清理当成本次顶部缺块的已证实原因。

| 检查对象 | 实心方片 | 描边方片 | 外层677px容器 |
|---|---:|---:|---|
| 源正文 | 2 | 2 | 有 |
| 默认复制后真实剪贴板 | 1（仅文末） | 2 | 丢失 |
| copy事件显式写入完整HTML后 | 2 | 2 | 保留 |

修复后的系统剪贴板去掉浏览器添加的charset meta后，与源正文逐字一致；将该真实HTML重新载入浏览器，确认两个实心和两个描边方片仍在，圆角3px。微信编辑器保存及手机显示需独立验证，不能用这个结果代替。

- 使用公共模板的copy事件写入完整`text/html`与`text/plain`；只有事件确实处理成功才提示已复制，失败不引导回有缺陷的手动全选路径。
- 自动回归：`node --test scripts/test_preview_copy.cjs`。检查首尾空装饰逐字保留、纯文本、监听器清理、无clipboardData不假报成功、异常和兼容拦截。
- 修改复制算法时还需一次真实系统剪贴板读回：记录源HTML和复制HTML首尾节点、样式、外层容器及计数。保存原剪贴板数据于内存，完成后恢复；不打印用户原有剪贴板内容。不以模拟execCommand返回true替代此项。
- 历史其它方案：零字号空格＋厚边框有用户报告保存后消失，具体转换机制未读取确认；文字方片可保存，但手机错位和圆角不符合设计；PNG保留为可选备用，内嵌图片是否被微信接收尚需实测。这些都不是本次复制裁切的根因修复。
- 向前一格当前纯HTML图标18px、单片8px、圆角3px；用户已确认正文／封面8px额外边距，正文16px／1.8不变。粘贴、保存后重开、手机预览分别记录。
- 小步生长按用户要求也采用正文、刊头、封面外侧和文末左右8px；检查cover、brand、完整骨架与组件预览同步，导语卡内部17px及引文卡内边距保留，正文16px／1.8不变。用实际文章在320px／390px检查无重复内收或溢出。

### 晴空手记（原摸鱼蓝）及同系多色导读与互动图标回归

- 2026-11-18作者微信手机预览反馈：横滑可用，但后两张导读标题多折一行、高度不齐。旧版固定110px且未明确box-sizing；在本地把卡片切为border-box即可复现，后两张标题高度22.75px→45.5px。未读取微信实际DOM，不把模拟当作平台内部规则。
- 改为卡片width:auto、min-width:144px、显式border-box及nowrap，三张相同padding与1px边框。320px／390px检查三卡标题与说明完整、等高、横滑可到最后一张；替换更长短标题时卡片应变宽，不能仍固定144px。保持正文16px／1.8。
- 文末按作者要求复用摸鱼绿原版点赞／眼睛／转发SVG，路径、viewBox、20px尺寸和1.8描边一致，仅主题配色改蓝；组件、骨架、组件预览和实际文章同步。不能再用“赞／看／享”字符替代。微信粘贴、保存及客户端仍分别记录结果。

### 本地检查

兼容性回归：`python3 -m unittest discover -s scripts -p 'test_*.py'`。覆盖嵌套span的start／end、默认外层对齐、后代文字渐变、无文字装饰、br／img节点、样式覆盖及严格模式退出码。复制回归运行上述Node用例；更改复制算法后补真实剪贴板读回，保留和恢复用户原数据。

改了组件库或 SKILL 后，按这个闭环验证，确保不引入排版反模式（大空白、左对齐占位、正文虚线框、平台禁用项）：

1. **改** 组件库 / SKILL / 脚本
2. **源头关**：`python3 scripts/component_lint.py .`
   扫所有组件库的 ```html 块，检测 `white-space:pre`（大空白）、四周虚线框 `border:…dashed`（正文，居中占位块豁免）、平台禁用项（div/class/id/style/grid/position/var/@media）。须 **0 ERROR**。
3. **生成** 用改后的 skill 排版 `assets/sample-article.md`（或真实文章）
4. **产物关**：`python3 scripts/validate_gzh_html.py --strict <产物.html>`
   检测禁用标签、`<span leaf>` 包裹、半角标点、对齐和含文字的渐变。须 **0 ERROR、0 WARNING**；无文字装饰渐变不报警。
5. 任一关不过 → 回第 1 步，直到两关全绿。

两脚本分工：`component_lint`检查组件库源头，`validate_gzh_html`检查装配后的正文；预览复制前再检查浏览器计算样式。源头通过不能保证后续装配与剪贴板转换正确，三层检查均不能替代微信编辑器及手机客户端验收。
